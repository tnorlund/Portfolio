## 1. Relocation complete and backend-neutral

`formatting` and `openai` now live under
`receipt_embeddings/receipt_embeddings/`. The first implementation commit
records all ten files as Git renames with 80–100% similarity so file history
follows the move.

`receipt_embeddings/tests/test_backend_neutrality.py` parses every Python
module and the package dependency list. It rejects any `chromadb` import or
dependency. A subprocess contract also imports both relocated packages and
proves that doing so does not load `receipt_chroma`.

Result: the complete `receipt_embeddings` suite passed, 56 tests.

## 2. Shim completeness and unchanged consumers

The old package and leaf-module paths are thin `from receipt_embeddings...`
re-export shims with explicit `__all__` declarations. The compatibility test
imports every old/new module pair and scans every checked-in Python import
site to prove that each requested old-path name still resolves.

The full `receipt_chroma` suite passed through the shims: 583 passed and 7
intentionally skipped. The downstream `receipt_upload` suite passed with its
existing intentional skips, and `receipt_agent` passed 387 tests with 22
intentional skips.

Because `receipt-embeddings` is an unpublished monorepo sibling, the package
metadata, local bootstrap, CI jobs, all 14 Chroma-consuming Dockerfiles, and
their explicit CodeBuild upload contexts install or include it. The Docker
package-context contract passed all 3 tests. Built wheels contain all ten new
implementation modules and all ten old-path shim modules.
